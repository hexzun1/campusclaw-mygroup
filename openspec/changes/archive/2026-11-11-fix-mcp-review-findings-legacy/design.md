# Design

## Context

动机、四个代码位置与触发时序见 [proposal.md](proposal.md)。当前没有进行中的 change，基线为 `openspec/specs/` 及以下归档：

- `2026-10-26-add-mcp-tools-and-api-tests`、`2026-10-27-fix-mcp-review-findings`：MCP 候选、两轮/三次预算、逐班授权、断开清缓存与审计。前次修复没有覆盖模型生成调用期间的撤权。
- `2026-09-30-add-auth-rbac-class-knowledge`、`2026-09-30-switch-to-jwt-bearer-auth`、`2026-10-16-add-tutor-agents-skills-streaming`：用户名与 IP 限流、JWT 与当前身份回库、SSE 协议及助手页。生产 `frontend/nginx.conf` 的 `/api/` 已设置 `X-Real-IP $remote_addr`，后端只读 `RemoteAddr`；生产 Compose 只暴露 web，开发 API 可直连。
- `2026-09-30-add-traceable-vector-retrieval`：先删向量再换切片的失败语义，按材料的进程内索引锁与单实例假设。当前 `Indexer.IndexMaterial` 的锁只包住读 pending、嵌入、写向量和状态更新，不能保护调用它之前的删除/替换。
- 当前 `createSSEParser.end()` 会刷新解码器并派发尾部残留帧，`streamConversation` 没有记录终态；`AssistantPage` 只在终止回调或 catch 中修改本轮状态，finally 只删 controller。

所有检查均为只读代码核对，未运行程序复现；这些观察不代表修复或验收已完成。本次按默认 `spec-driven` schema 仅创建 Markdown，沿用 CLI 解析的项目配置，不生成非 Markdown 的变更元数据文件。

## Goals / Non-Goals

**Goals:**

- 把“本轮候选可用”与“本次调用获准”分开，明确撤权和准入的先后边界、拒绝分类与审计证据。
- 在服务端可信代理边界内恢复用户名与真实客户端 IP 的限流隔离，并防止伪造头改变桶。
- 让同材料的索引变更形成完整串行序列，以数据库当前切片集合与向量集合的精确比对验收。
- SSE 客户端所有退出路径均能结束本轮状态，正常终止与错误/主动取消可区分，保持既有事件和回调兼容性。

**Non-Goals:**

- 不扩大 proposal 中的四项修复范围；不在本轮实施、启动依赖服务或执行验收用例。
- 不承诺跨实例互斥、跨存储原子提交、同一 NAT 出口内的设备隔离或对已经发生的 MCP 副作用进行回滚。
- 不改变身份授权来源；权限与班级过滤继续在服务端执行，不采信前端按钮、客户端 class_id 或旧候选中的身份。

## Decisions

### D1 MCP：为每次调用增加独立的服务端准入读取

保留 `Resolve` 作为模型候选筛选；在 `runCall` 的候选、次数/时限和参数检查之后、进入 `Client.Call` 之前，执行新的调用专用目录操作，按 `(serverID, classID, toolName)` 获取仍有效的调用凭据与当前地址。此操作只返回满足本班、connected、当前缓存含工具的结果，不把候选保存的 BaseURL 或前次令牌作为授权凭据。

使用短数据库事务，与现有 `DisconnectServer`、`ReplaceServerTools`、`MarkServerError` 的服务器主键锁遵守同一顺序：先按编号与班级锁定服务器行进行当前读，再复核工具缓存，全部满足后读取凭据，结束事务。断开/缓存替换本来就先锁服务器，因此不得在检查缓存后才反过来锁服务器。事务和远端网络 I/O 分离，MUST NOT 持有服务器行锁等待远端响应。

**并发语义**：短事务核验成功是本次调用准入点，断开事务提交是撤权生效点。撤权在前，则此次及随后准入一律拒绝；准入在前，则该单次操作按在途调用处理，可继续其 MCP 握手和 tools/call，不强杀远端副作用，且不阻塞教师断开。凭据只用于紧接的该次 `Client.Call`，不得排队供后续调用或重试复用；若将来增加异步排队/重试，执行新操作前必须重新准入。这里没有承诺撤权后网络上绝无在途字节；承诺的是撤权后不再准入新的调用。用数据库锁与测试屏障确定先后，不以 goroutine 启动顺序代替提交顺序。

**错误映射**：

| 条件 | status / reason | 行为 |
| --- | --- | --- |
| 候选外 | denied / not_allowed | 沿用现有校验，不调用远端 |
| 本班授权已失效、服务器消失/他班、工具缓存失效 | denied / not_connected | 不返回可用凭据，回传统一拒绝信息 |
| 数据库读取失败 | error / remote_error | 安全拒绝调用，通用失败信息，不伪装成撤权 |
| 远端 HTTP/协议/工具失败 | error / remote_error | 沿用现有失败回传 |

`remote_error` 继续包含当前代码已有的凭据读取故障，避免扩大 reason 枚举；用 status/reason 已能把撤权和普通失败区分。候选内被拒仍占现有三次预算，运行中拒绝用实际 round，而不是 Resolve 专用的 round 0；审计、meta、回传模型的信息保持一致且无令牌。

**连接兼容**：`backend/internal/mcp/handlers.go:277–305` 的 `Connect` 也使用 `GetServerToken`，必须允许读取本班 disconnected/error 服务器的凭据以尝试连接。因此不能直接给共享 `GetServerToken` 加 `status=connected` 而让连接无法启动；保留连接专用的班级检查读取，工具执行走新的受授权读取路径。明确教师重新连接成功可恢复后续调用，不追溯修改 denied 记录。

备选：仅在每轮开始重跑 Resolve 会漏掉同批调用；分别读取状态与令牌会有检查与使用间的过期窗口；在整个远端调用期间持行锁会阻塞撤权数秒。选用短事务逐次准入，成本是每次候选内合法调用多一次小事务，受既有三次调用预算约束。

### D2 登录：只信任受控直接代理的 X-Real-IP

新增服务端可选环境变量 `TRUSTED_PROXY_CIDRS`（逗号分隔 IP 或 CIDR，空为不信任任何代理）。启动时校验并规范化，拒绝非法项及全网 `/0`；不将“私有地址”“回环地址”自动视为可信，不从请求头推导代理身份。配置里出现受控代理范围不等于整个 Docker 网段天然可信：被包含的任何可直连 API 的工作负载都有伪造头能力，运维必须把范围收窄到受控代理来源。

地址选择流程：

1. 解析 `RemoteAddr` 的 IP 并规范化，去掉 TCP 端口；解析失败直接 400，不访问 limiter。
2. 对端不在信任列表：使用该 IP，忽略 X-Real-IP、X-Forwarded-For、Forwarded。
3. 对端在信任列表：要求恰一个 X-Real-IP 头值，trim 后必须为单个 IPv4/IPv6 字面地址（无端口/zone/逗号）。不合格返回 400，不读取、增加或清除任何桶；合格后规范化（包含 IPv4-mapped IPv6 的 unmap）。
4. 将用户名与规范化地址构成无歧义的二元 key，保留用户名现有匹配口径、不额外改大小写或空白。锁定检查、失败计数、成功重置必须使用同一个 key。

`X-Forwarded-For` 可由公网客户端拼接或在多级代理中携带不可信左端，任意选首个/末个地址都可能绕过限流或封禁他人；当前是单 Nginx 入口，没必要引入多跳链解析。Nginx 当前覆盖 X-Real-IP 的行为足够，不能改为透传客户端同名头。

**为何非法可信头返回 400 而非回退**：回退到代理 IP 会再次把所有来源聚合，正是本次缺陷；拒绝不消耗任何桶，让代理配置错误可以定位。这个 400 是请求/代理地址错误，不区分用户名存在性；合法地址下错误口令、账号不存在和锁定继续统一 401。默认 5 次/300 秒、内存限流、成功清零及到期恢复维持不变，用受控时钟测试而不真实等待。

备选：无条件优先 X-Real-IP 会让开发直连与内部调用任意选桶；仅依赖“生产 API 不暴露端口”不足以约束同网络来源；按用户名全局封禁直接保留第三方封禁能力。显式代理列表是本变更选择，部署取值见 Open Questions。

### D3 索引：复用同材料锁，覆盖完整重建生命周期

保留现有进程内按 `materialID` 的锁粒度（材料主键在库内全局唯一），不改为全局锁。由 `internal/index` 的同一个协调器提供同材料的执行边界，所有 `IndexMaterial` 调用与 `Reindex` 使用相同锁实例；不能在 handler 另建一把互不相关的锁。

角色/班级/参数检查在破坏性工作之前完成，获取资格后再次检查取消状态及需要更新的材料身份。持锁期间依次完成：读本次输入 → 删除该材料/班级的向量 → 事务替换切片及参数 → 嵌入并写新向量 → 更新或失败标记 → 读取统计构造不可变响应值；释放后再写 HTTP 响应。即使后一请求立即开始，前一响应中的统计也不被替换。

为避免重入死锁，把索引实现拆成“对外自行获取材料锁的入口”和“已处于材料临界区的内部实现”；重建从内部路径索引，不再次调用会获取同一非重入锁的入口。上传后的索引、启动补偿及直接索引继续经外部入口。锁释放覆盖所有 defer/失败分支，取消的排队请求即便稍后取得锁也不得开始删除；等待和远端操作均不持协调器的全局 map 互斥锁。

保留删除失败 503、切片事务回滚、索引依赖失败保留切片并标 failed 的原有语义。`IndexMaterial` 已使用独立超时、不随调用者断开取消；重建进入此阶段后也必须持材料锁直到其写向量与 `markFailed` 真正结束，不能因 HTTP 请求取消就提前放锁。切片替换失败时的 `materials.markChunksFailed` 同样在资格内完成（有界超时、尽力而为）。业务记录仍按 class_id 过滤，锁本身不提供权限。

验收用屏障固定 A 读完切片未写向量、A 删完向量未替换两种时序，再启动 B；记录每个操作，不用任意 sleep 充当互斥证据。全部成功后按 `(class_id, material_id)` 枚举 Qdrant 点，与 MySQL 当前 chunk ID 做集合相等及数量断言，再用确定性嵌入检索当前内容。仅断言接口 200 或“检索结果不含孤儿 ID”不足以证明没有残留，因为回表本来就会丢弃孤儿。

备选：全局锁最简单但阻塞无关材料；只锁 handler 能漏掉上传/补偿；用 MySQL 长事务覆盖 Qdrant 网络操作既不能原子提交两库又占连接；版本号切换或分布式锁涉及数据结构和多实例，不纳入本次。保留单实例互斥，针对同材料增加等待是必要成本。

### D4 SSE：显式终态与唯一错误出口

在 `streamConversation` 层维护“尚无终态 / done / error”及是否收到 meta；解析器继续只负责按字节组帧。分派前先检查终态，已结束则忽略迟到事件。done 只有在 meta 之后且 message_id 为正整数时有效；error 要求非空字符串 message；先校验 payload 再标记终态或调用回调。合法终态立即结束消费、取消/释放 reader，不等服务器 EOF；同一个字节块里的重复帧由终态守卫忽略。

EOF 先调用 `parser.end()` 再检查终态，保留现有尾帧没有空行但 JSON 完整的容忍行为。尾帧解析报错或仍无终态时，抛出通用中断错误（可沿用 `ApiError` 的客户端失败表示，status 0，不冒充服务器 HTTP 状态），让 `AssistantPage` 现有 catch 把 pending 变为 error。读取异常与坏终止 payload 也走同一个通用错误出口。

**通知兼容与去重**：有效 done 调用 onDone 一次；有效 error 调用 onError 一次，沿用“错误已经由回调处理，Promise 可结束”的接口语义，不能在 EOF 再抛一次；缺失/无效终止与读取故障通过 Promise rejection 通知调用方，不再同时调用 onError，避免同一个故障在 callback 与 catch 中处理两遍。因此无终止事件的请求明确拒绝，绝不无声 resolve。以 API 调用测试断言回调计数与 Promise 结果，再验收页面状态。

finally 释放读取锁，终止/异常路径取消剩余读取；清理异常不得覆盖原始业务结果。页面保留 partial answer、meta，显示「回答生成中断，请重试」并清理 controller 登记，不伪造 done，也不因为流中断而清 token。用户切换/离开时 AbortSignal 优先按主动取消处理，保持 AbortError 的静默行为，旧流的迟到帧不得更新新页面；当前页面没有独立“停止生成”按钮，不新增该交互。

备选：EOF 直接调用 onDone 会把未完成正文冒充成功，且没有可靠 message_id；仅在 UI finally 清 pending 缺少明确错误结果；让 parser 负责协议终态会把纯分帧与业务状态耦合。选择流式 API 层状态机，保留 parser 的编码、换行和尾帧兼容行为，不更改服务端协议与已落库语义。

## Risks / Trade-offs

- [已准入的 MCP 操作仍可能在撤权后返回或继续发出其在途协议请求] → 明确以单次即时准入排序，不承诺撤回已准入操作；下一调用必须重新校验，且不等待远端响应才允许断开。
- [代理白名单过宽可使被包含的其他容器伪造 X-Real-IP] → 默认不信任，生产部署选择仅覆盖受控代理的来源范围并验证入口；空列表虽然安全地不信头，但不能修复生产代理聚合，不能省略生产配置验收。
- [共享 NAT 的同名用户仍共用一个桶] → 维持既有用户名+IP 口径，设备级识别另议；本变更保证不同真实 IP 不再因同一个 Nginx 而合并。
- [同材料重建等待更长，远端超时收尾延迟下一任务] → 沿用有界索引/失败标记超时，不提前放锁；不同材料互不阻塞。
- [进程崩溃或存储服务异常不受进程锁覆盖] → 本变更保证并发正常结束的一致性，依赖失败保持诚实状态并可重建恢复；不声称已经清理历史孤儿点或实现分布式事务。
- [旧代理截断终止帧现在会显式报错] → 这是预期修复，保留部分内容与既有有效帧兼容；不自动重试，避免重复提交问题。

## Migration Plan

仅为后续实施方案，本轮不执行以下操作。无需数据库迁移、清空存量数据或全员重新登录。实现经本 change 的 Scenario 验收后，部署方须先提供受控代理的精确来源列表，并验证 Nginx 覆盖 X-Real-IP；直连开发默认空列表。后续正常发布使用该配置的 API 与前端资源，保留现有服务边界。

存量材料不做全库扫描；已有残留可在修复发布后由本班教师针对材料重建，验收前后点集合。SSE 无新字段，前后端不要求数据库联动升级。回退 API/前端构件不需要回滚数据结构，但会恢复旧缺陷，不能把回退当作安全修复；历史规约与任务勾选不在本次修改。

## Open Questions

- **部署时待确认**：生产 Nginx 在 API 侧可验证的来源 IP/CIDR 具体是什么，是否有额外外层代理？仓库仅证明当前 Compose 单 Nginx 拓扑，没有真实运行网络地址。采用上述单受控代理设计不变，填入白名单的实际值由部署者确认；若存在多级代理，先校准入口的真实来源覆盖策略，不能临时改用不可信 X-Forwarded-For。
- **验收环境待确认**：实施阶段在哪个隔离测试环境提供可用 MySQL/Qdrant 与两个不同源 IP 的入口请求？测试方法与断言已确定；未取得条件时对应集成/入口场景必须标为未验证，不能以单测通过代替。

没有遗留的行为口径选择；这两项是实施/部署环境信息，不阻塞规约评审，也不授权本轮修改配置或启动环境。
