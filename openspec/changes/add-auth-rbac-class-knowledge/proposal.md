## Why

CampusClaw 是面向中小学的教研智能体，教研材料与知识库是其能力底座。当前材料分散在群文件与网盘中，教师难以检索复用，班级之间也缺少数据边界。本变更（迭代 1）先建立**身份、角色与班级隔离**，让教师登录后上传本班材料、学生只能查看和下载本班内容，为后续检索与智能问答打好地基。

## What Changes

- **用户登录与会话**：教师、学生两类角色；账号密码登录；服务端会话 + HttpOnly Cookie；登出后旧 Cookie 立即失效；登录失败统一提示并按"用户名 + IP"限流；`GET /api/me` 返回当前角色与班级。
- **角色权限**：教师可上传、查看、下载本班材料；学生只能查看和下载；学生调用上传接口 MUST 返回 403。
- **班级隔离**：班级为数据边界，只取自服务端会话；列表、详情、文件下载都在服务端按班级校验；跨班访问与记录不存在统一返回 404。
- **材料上传与知识库入库**：教师上传 `.txt` / `.md`，服务端校验扩展名、大小与编码后，在同一事务内写入材料表与知识库表；本班列表查库可见；原文件只能经鉴权接口下载。
- **前端页面**：登录页与材料页（列表、本班搜索、详情、下载、教师上传），前端通过同源 `/api` 调用后端，身份以 `/api/me` 为准。
- **预置样本数据**：班级 A/B、教师 A、学生 A1/B1，两班各有标题可区分的材料；种子幂等。
- **安全与部署**：口令 bcrypt 哈希；会话密钥、数据库凭据、预置账号口令全部走环境变量，缺失即启动失败；Docker Compose 启动 web（Nginx + 前端）、api（Go）、db（MySQL）三个服务，只暴露 web 端口；提供 `GET /health`。
- **文档**：README 写明范围、不做项、启动方式、预置账号、跨班返回码与单实例说明。

## Impact

- 新建后端 `backend/`（Go + 标准库 net/http）：登录/登出/me、材料列表/详情/下载/上传、健康检查。
- 新建前端 `frontend/`（React 18 + TypeScript + Vite）：登录页、材料页。
- 新建 MySQL 8.0 表结构与种子：classes、users、sessions、materials、knowledge_entries。
- 项目根新增 `docker-compose.yml`、`.env.example`、`.gitignore`、`.dockerignore`；web 与 api 各有 Dockerfile，web 含 Nginx 配置。
- 技术栈由第 2 课初稿的 Flask + SQLite 调整为 Go + MySQL + React + Nginx，理由见 design.md。

## Non-goals（非目标）

本迭代**明确不做**以下内容（表结构可预留字段，但不实现、不验收）：

- **检索与问答**：不做知识库问答、全文检索、向量检索、RAG、跨班检索。本班列表内的前端筛选不算检索。
- **对话与教学流程**：不做对话助手、Agent 编排、技能运行时；不做作业布置、提交、批改、成绩与错题本。
- **账号体系扩展**：不做注册、找回密码、改密；不做多校/多租户；不做验证码、邮箱或短信登录。
- **其他登录方案**：不做 JWT、OAuth、SSO；不把会话 ID、角色或 token 存进 localStorage。
- **平台超级管理员**：产品完整形态里必然存在，但它天然跨班，会与"跨班返回 404"的隔离验收冲突；留待隔离稳定后单独开变更，设计其越权路径与操作审计。
- **复杂文件**：不做 PDF、Word、图片解析，不做在线预览与编辑。
- **生产运维**：不做 Kubernetes、CI/CD、公网域名、HTTPS 证书、多副本高可用；当前为单实例 Compose。
- **前端替代服务端安全**：隐藏按钮、禁用表单都不构成访问控制；用 curl 能绕过的实现不算完成。
