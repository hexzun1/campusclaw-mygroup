# Proposal

## Why

`add-mcp-tools-and-api-tests` 上线后（提交 `02cfd74`），一次 `/code-review`（high）在 MCP 相关代码中报告了 10 条问题。其中几条直接违反已归档规约的承诺：客户端断开会让审计丢失、一条超长函数名会让整轮审计回滚、远端可通过工具结果把令牌带进模型上下文。另外几条会让合法的第三方服务器连不上，或让 `connect` 被用来探测内网。这些问题需要先补进规约，再修代码。

## What Changes

审计与调用循环（`mcp-tools`「调用审计」「工具调用循环」）：
- 审计写入改为不随请求取消：客户端在工具阶段断开后，已发生的调用记录 MUST 仍然落库。
- 审计写入前把工具名、服务器名截断到列宽（64 / 32）。模型编造的超长函数名不再让整轮审计回滚。
- 「累计最多 3 次调用」改为只计候选集内的调用。`not_allowed` 不占这 3 次名额，但单个工具阶段的调用请求总数另设上限 10 次，防止模型用大量幻觉调用刷审计。**BREAKING（行为口径）**：原来"4 次请求里第 4 次必为 limit"的场景，在前几次含 `not_allowed` 时结果会不同。
- 成功结果文本在注入模型之前 MUST 去除该服务器令牌原文。

连接与登记（`mcp-tools`「工具服务器登记与管理」「连接与工具发现」）：
- 主机发往远端的 `Accept` 只声明 `application/json`，与"只用单个 JSON 响应、不用 SSE"的口径一致。
- **防 SSRF**：
  - 不跟随任何 3xx 重定向，3xx 视为连接失败。
  - 拒绝以下目标：回环地址、链路本地地址（含 `169.254.169.254` 元数据地址）、未指定地址（`0.0.0.0`、`::`），以及本编排内的 `db`、`api`、`qdrant`、`web` 服务名和 `localhost`。
  - 校验发生在两处：登记时检查字面地址，连接和调用时检查解析后的实际 IP，以防 DNS 指向内网。
  - `mcp-demo` 和其它内网地址照常允许。**BREAKING**：以 `http://127.0.0.1:...`、`http://localhost:...` 登记的服务器将被拒绝。
- 发现结果中重名的工具只保留第一个并记日志。写缓存失败时也把服务器置为 `error`，记录可读的 `last_error`。
- 令牌长度改为按 UTF-8 字节计（1–512 字节），与 `VARBINARY(512)` 一致，超长返回 400 而不是 503。
- 超时提示分为两类：握手阶段超时为「连接超时」，`tools/call` 超时为「调用超时」。
- 删除服务器与保存技能互斥：删除时的引用检查和保存时的服务器状态检查都在加锁的事务内进行，不再留下悬空引用。

纯实现层面（不改规约）：`backend/internal/mcp/client.go` 未经 gofmt，需要格式化。

## Capabilities

### New Capabilities

（无）

### Modified Capabilities

- `mcp-tools`：修改以下 5 条要求：
  - 「工具服务器登记与管理」：令牌按字节计长度、地址黑名单、删除与保存互斥。
  - 「连接与工具发现」：Accept 头、拒绝重定向、解析后 IP 校验、工具重名去重、写缓存失败置 error、超时文案。
  - 「技能对 MCP 工具的引用校验」：校验在保存事务内加锁复核。
  - 「工具调用循环」：调用计数口径、请求总数上限、结果文本脱敏。
  - 「调用审计」：不随请求取消、字段截断。

## Impact

- 后端：
  - `backend/internal/mcp/`：client.go 的拨号守卫、重定向策略、Accept 头、超时分类与结果脱敏；handlers.go 的地址黑名单、令牌字节长度、去重、写缓存失败置 error。
  - `backend/internal/tutor/`：toolstage.go 的计数口径与请求上限；stream.go 改用 `context.WithoutCancel` 写审计；skill_tools.go 及技能保存路径的加锁复核。
  - `backend/internal/db/`：mcp.go 的审计截断与删除事务；tutor.go 的 CreateSkill/UpdateSkill 在事务内锁服务器行。
- 测试：
  - Go 单元测试中以 `httptest`（127.0.0.1）充当远端的用例，需要通过可注入的拨号守卫放行回环地址，生产配置不放行。
  - apitest 用例的登记地址都是 `http://mcp-demo:8090`，不受影响。新增若干用例：黑名单地址、多字节令牌、审计截断。
- 数据库：无结构变更，无需迁移。
- 文档：`docs/iteration-5.md` 记录验收证据；swag 注解中的 400/502 描述同步更新。

## Non-goals

- 不做主机白名单，也不新增 `MCP_ALLOWED_HOSTS` 配置。黑名单只覆盖本编排已知的敏感目标和保留地址段。
- 不阻止私有网段（10/8、172.16/12、192.168/16）：`mcp-demo` 就在 Docker 私有网段里。
- 不支持 SSE 响应，也不支持会话恢复。
- 不改变令牌明文存储的方式，也不做令牌加密。
- 不改变 `round`、`status`、`reason` 的取值集合，也不改变 `meta.tool_calls` 的结构。
- 不追溯修复已经存在的悬空引用。
